# HATCH EXPLORE-01

November 2, 2026 (America/Phoenix). Full checkpoint over CABINET-01 / POEM. This is the capability-launcher and menu slice of the Interface Companion, with the earlier Hatch workflows preserved.

## The new entrance

Explore sits at the bottom left beside the existing five-command Hatch. It opens a stable menu of 15 existing workspace adapters and a retained central workshop browser. The browser brings together these workspace routes, all 12 authored method profiles, all 684 canonical operations and all 112 job tools. The combined read view has 823 entries before filtering. Workspaces are the default category; methods, operations, job tools and the complete view have separate filters and bounded pagination.

The new `ledger.explore` operation is read only. It is a projection over the original capability catalogue and Algorithm & Theory Atlas, with presentation adapters for existing GUI factories. It creates no alternate store, execution dispatcher, grant, source record or learned procedure. An exact operation or tool opens its existing Tool Atlas contract. A method opens the existing Algorithm & Theory Atlas. A reference-only method is explicitly identified and offers inspection rather than execution.

Search accepts subjects, familiar tool names and exact operation IDs. It ignores a small documented set of common request words so a phrase such as “I want to test an idea” can find the actual inquiry controls. This is deterministic metadata matching, not an inference call, semantic proof or general natural-language planner. All editable entry hints retain the owner's exact invitation: `poem`.

## Work-aware suggestions

Opening Explore from a cabinet record carries its stable ID and caller-checked metadata. An idea or project offers questions, calculations and the existing laboratory; an inquiry offers methods and tool inspection; a working copy offers its established file and Office controls. Each suggestion explains its record-kind basis. It does not claim method applicability, a proven scientific result, or permission to execute. The record's original body is not copied into the projection.

Explicit read actions supplied by the cabinet, such as checking an inquiry's bindings, retain their original operations and caller checks. Search and selection do not run those actions. Unavailable or other-owner records yield a generic context notice without disclosing their ID, title, body or action list. Explore is included in the existing cloud-private operation boundary; local read-only inspection does not grant effectful scope.

## Presence, readiness and running state

Workspace source presence and registered family operations determine whether a GUI view can be opened. Tool prerequisites reuse the canonical passive native assessment: missing or incompatible tools need setup, detected files still need checks, and unassessed dependencies remain unassessed. Opening a view is separate from qualifying or running its instruments.

Active-job counters are bounded, owner filtered and based on stored Kernel jobs. Running and queued counts are reported separately; they do not claim live process ownership or CPU scheduling acceptance. Oversized or truncated metadata produces a visible counter notice. GUI “view already open” is derived from actual current workspace widgets. A source/registry check repeats before opening a frozen menu entry. The menu itself holds one snapshot steady while the owner chooses.

## Preserve the writing

Explore is an existing-policy Room. Its launches use the original factories inside a scoped retained-view context; newly created views stay open without replacing an edited Preview or consuming its five-pin allowance. Ordinary navigation outside that context retains its original policy. Reopening an existing inquiry never reloads or replaces its unsaved wording. Cabinet records also gain Explore this work. Selection, tree expansion, original identities and master protections remain in their established stores. This slice does not add durable recovery for unsaved buffers beyond the existing mechanism.
