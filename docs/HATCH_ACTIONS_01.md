# HATCH ACTIONS-01

November 2, 2026 · America/Phoenix

Complete checkpoint over OPERATIONS-01. The logical cabinet now presents a
compact **With this record** shelf and a right-click action menu. Both use the
same new read operation, `ledger.cabinet.actions`, available to local Slate and
the ordinary CLI/MCP command paths. This is a bounded contextual-action slice,
not a new scheduler, execution dispatcher, or model/native qualification.

## Selection and ranking

The read operation resolves the selected cabinet placement through the existing
owner-scoped `cabinet.get`. It returns only selected metadata, a digest of the
already-read saved record, ordered action metadata, and a signature. It does not
return the record body. Missing, private and stale identities receive one generic
unavailable response without echoing the requested ID or provider exception.

Order follows a declared rule: saved-record inspection; preparation of an
existing writing form when applicable; the provider's existing explicit read
checks; related workspaces from Explore's record-kind suggestions; all-capability
inspection. There is no numerical confidence, inferred method fit or model call.
Only the first three actions appear on the shelf; All actions and right-click
expose the complete same list. References retain both their placement ID and
canonical identity. A reference does not become ownership or project membership.

## Eligibility and invocation

States are READY, NEEDS_INPUT and UNAVAILABLE. Required scopes, Tutor mode,
registered read command contracts, presentation sources and workspace command
presence are checked. Unavailable actions remain visible with a specific reason.
Checks not performed yet are listed in the shared metadata and tooltips.
Opening a workspace does not establish native/runtime readiness.

Before any Qt action, the controller recomputes the model for the identity
captured when the shelf/menu was built. It refuses a changed signature and never
substitutes a later tree selection. The saved-record digest catches providers
whose note revision is separate from their tree object's revision. This digest
does not hash a master file or establish source freshness. The original command
still performs current provider, input and access checks; this is not a database
transaction spanning menu presentation and provider execution.

READ actions dispatch the exact existing read operation and show its current
result. Only registered read commands with valid arguments can be advertised as
reads. PREPARE actions focus the existing project/idea writing space and retain
its draft. The separate Keep/Create button submits writing. WORKSPACE actions use
the original Explore navigation with no automatic record binding, copying,
project reassignment or edited-input replacement. EXPLORE opens the retained
workshop. Failed cabinet opens now return None instead of a misleading prior
room. Existing cabinet record actions and all earlier routes remain available.

Discovery reads are passive metadata inspection. Existing dispatch auditing and
provider initialization can still write operational metadata; no claim of zero
SQLite writes is made. Cabinet actions are covered by the existing cloud-private
cabinet prefix and are an observer operation to avoid polling journal noise.
