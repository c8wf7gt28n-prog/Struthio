`ledger.settings.set` retains its existing arguments and gains optional `expected_revision`. This fingerprint includes the saved value and latest setting change ID, so a value changing away and back still conflicts. The editor uses it automatically; `/set` does too. Legacy expected-value writes remain supported. Undo refuses a superseding revision and records restoration plus the original record's undone flag in one journal transaction. The existing external-profile delivery receipts still recover interrupted writes and undo receipts.

Saved visual values do not imply active desktop effects. Live consumer receipts include profile and process identity and require a desktop lease. Fonts show their resolved fallback. A concurrent write updates the saved/effective display while retaining the highlighted draft and its original revision. Reload saved value is an explicit replacement of that key's draft. Draft retention across process exit is not implemented; Apply saves the actual setting.

The existing selected-settings ViewContext now follows the left key. Structured settings context includes saved/effective state and revision. Raw credentials are absent. Existing provider, AI admission and service-admission owner boundaries apply to Set, Default and Undo.
