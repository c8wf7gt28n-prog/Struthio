## Typed application handoffs

The source-bound schedule receipt identifies the problem revision, context digest, selected quantities/lifetimes and source copies. A prepared joined action freezes that receipt, engine identities and component hashes. It is a descriptor, not execution permission.

The chain writes only its owned job outputs:

1. **Calc quantity table.** A generated ODS contains numeric inputs and explicit half-open demand formulas. Native Calc recalculates, saves and reopens it. Both measured phases are compared with the exact source schedule; formulas and declared numeric precision are checked.
2. **Python quantity observation.** The protected fixed Python experiment checks the actual ODS SHA-256, consumes the values measured after Calc reopened it, independently recomputes demand and verifies agreement. The experiment's actual output is schema/unit checked.
3. **Writer checked findings.** Native Writer receives the validated quantities, conditional wording and source/parent identities. The saved DOCX is reopened and its table and citations checked. Native PDF export is retained as another linked artifact.

Artifacts live in the existing owner-scoped Desk store and protected byte-object store. Each contains its type, problem/context revision, immutable byte identity, current working file, parent artifact references and optional exact method version. A path is never the handoff's identity. A changed parent, file, source, engine/component binding or accepted method makes dependent active results stale. Immutable earlier bytes and Desk history remain retained.

The schedule uses exact rational units. Calc uses native floating point, checked under the recorded absolute/relative tolerance and bounded numeric profile. Agreement is a consequence of the supplied model, not measurement of a physical system. Original source files remain unchanged.

## Owned working-file sessions

The **Working file** tab has **Open working file**, **Recalculate in view**, **Pause**, **Take over**, **Resume**, **Recheck edited inputs** and **Close owned file**. This path requires a usable X11 session (including XWayland via `DISPLAY`), a real Calc window handle and a current checked working ODS. A headless process or a painted placeholder cannot satisfy it.

The native session is a bounded existing Kernel job with its own Office profile/process group and a 540-second lease. It addresses the precise checked ODS, not a second demonstration workbook. A foreign window container can display the actual X11 window. Other Office documents and independently owned sessions have separate identities; there is no global Office kill.

Automation begins paused. Resume permits visible recalculation, whose numeric values are compared with the checked artifact before a visible observation is stored. Take over first holds conflicting copy automation and pauses conflicting continuing-work orders. It then enables owner editing. The numeric edit API accepts only declared input cells during owner takeover; ordinary owner interaction is still through Calc.

After editing, **Resume** compares saved bytes and retains an unchecked artifact revision. Dependent results become stale. **Recheck edited inputs** validates numeric cells and unchanged units, creates an explicitly owner-supplied scenario revision, and prepares a new exact schedule and application chain. Original source assertions/files remain intact. The interface runs that new chain and can reopen its checked working file. Interrupted scenario/continuation writes roll back together; a retry does not duplicate the source revision.

This session implementation is **not yet accepted on a real visible Calc session**. Its positive takeover/coordinator fixture uses injected command transport and real headless file edits; that fixture is explicitly labeled. Closing or reopening the application is not evidence of the native ownership and embedding behavior.
