# Ledger & Slate — UI mini pass

This separate UI checkpoint continues the saved I05 implementation. I04 was accepted in the carried checkpoint; I05 actual-model and visible Calc takeover acceptance remain open. I06 has not started. The prior test receipts are historical.

The owner requested this mini pass with **no tests**. No test suite, compilation checks, model runs or acceptance trials were run. The screenshots show the actual Qt application rendered offscreen in a disposable Office workspace. Two explicitly named screenshot-example Agenda items are queued with the runner stopped; neither was executed. Popup screenshots combine the actual window and its actual popup renders, because offscreen Qt exposes them as separate surfaces. They do not demonstrate lifecycle, priority or model behavior.

- Hatch is first in the console row, followed by Line, Half and Tall. It opens exactly New Idea, New Project, On, Off and Reboot, using the existing capture and Project Desk workflows.
- Transparent original SVG assets use the existing Paper/Struthio palette: graphite, pencil yellow and eraser pink. Four interaction states are included at 16, 24, 32 and 48 pixels. The 16-pixel icon omits the mushrooms.
- Hatch lifecycle actions confirm first. Off saves open work, closes a separate persistent admission gate to new Kernel work, pauses the desktop Agenda/idle runners, drains running work and stops the model and phone link. The existing emergency work hold is applied after the drain so it does not kill an in-flight job during graceful shutdown. Long-running work can keep it in a stopping state; Nice → Stop remains available. On explicitly releases the owner work hold and service admission gate. Reboot cycles these services in the current desktop, preserves open tabs and requests restoration of a previously running model when Slate is enabled. It never reboots Linux. Cancelled jobs and phone pairing are not replayed.
- The header has CPU, GPU, RAM and TXT in that order, an independent Slate ON/OFF switch, and Nice. Date and path widgets are hidden. GPU shows unavailable when the Linux driver supplies no utilization. TXT explicitly shows unavailable because the current runtime exposes no trusted live context occupancy; completion tokens are not substituted.
- Slate admission is a persistent owner-controlled setting. New local model activation, qualification and inference jobs are gated at submission and worker admission. Existing requests may finish. Ordinary Ledger tools remain available. The desktop cloud-chat entry and provider proposals also honor the switch.
- Nice keeps Stop fixed above its scrollable work lists. Dragging pending Agenda work commits its actual persistent scheduling order and adopts the neighboring priority tier. Each row also has a niceness slider: Agenda rows use Now / Normal / Background; Kernel jobs use Linux CPU nice values 0–19. Queued CPU requests are persisted and applied before job children start. Running-job changes target the identity-verified owned worker and its verified process descendants; partial changes and OS refusals are reported. Returning to higher CPU priority may be refused by Linux. Shared services outside that process tree retain their own priority. Independently executing Kernel jobs are not a serial queue and are not draggable. The existing overall background CPU policy remains available.
- Visible menus are File, Edit, Tools, Options, Commands, Settings, Properties and Help. Existing actions, shortcuts and contextual chain/Fluxbox pipe menus are retained. Settings uses a Ledger → Settings hierarchy with name, type, value and description, validated editors and the existing stores, defaults and undo.
- Trash is pinned at the bottom-right of the left navigation panel, outside the scrolling tree. Click or keyboard activation opens its contents. Existing recoverable file drops remain available.

The full design brief remains broader than this mini pass: native-host behavioral acceptance, running-process drag reprioritization, and a trusted live model-context occupancy feed remain future work. This checkpoint does not promote I05 acceptance. No files from the I05 archive were removed. Source bindings and the package inventory are refreshed as generated packaging data, without running the validation suite.
