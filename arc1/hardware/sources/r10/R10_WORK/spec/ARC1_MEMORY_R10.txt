Engineering Baseline v0.1   |   Prepared 15 October 2026
Executive decision
Lock the capacity target at 228 MiB of distributed working RAM. Pursue a single 64 MiB SPI NOR, owned by the F133, as the persistent system store. This single-NOR architecture is CONDITIONAL: the D213 must first be shown to start reliably without dedicated local boot flash.

Architecture decisions
F133 is the system authority; its NOR owns the boot manifest, images, and update history.
D213 controls graphics RAM, its own CPU firmware, and 2D/display operation.
45F owns 32 MiB high-bandwidth local 3D memory; 12F owns 4 MiB lightweight work memory.
No unified 228 MiB address space is implied: transfers between domains are explicit.
One NOR is the preferred minimal PCB implementation; two NORs remain the validated fallback if flashless D213 boot cannot be demonstrated.
Control status: MEMORY CAPACITIES — selected design targets. SINGLE NOR — proposed, not verified. PCB FABRICATION — HOLD until boot and interface gates pass.

1. Memory ownership and terminology
ARC-1 contains four independent execution domains. Each working-memory device belongs to exactly one domain. No part of the external SDRAM or PSRAM should be treated as globally coherent memory.

What these numbers mean
228 MiB is distributed working RAM; it is neither one 228 MiB memory bank nor a guarantee of one large contiguous allocation.
64 MiB NOR equals 512 Mbit. It is persistent firmware storage and cannot substitute for DDR/PSRAM.
SD storage is for game packages, music, large textures, user data and distribution; it is separate from the system NOR.
Each FPGA also contains embedded block RAM, but that small on-chip storage is excluded from the 228 MiB headline.

Non-negotiable ownership rule
The D213 cannot assume direct random access to the 45F SDRAM; the 45F cannot assume direct random access to D213 DDR3. PBUS transfers move defined buffers or tiles. Likewise, F133-to-D213 memory exchange requires a transport and driver, not simple pointer sharing.


2. Four RAM devices: preliminary electrical basis
2.1 F133-B — 64 MiB packaged DDR2
Main game logic, application code, audio state, input handling, collision/game models, F133 USB and system services reside here. DDR2 wiring does not leave the chip package in the proposed board. Bootloader and recovery must be small enough to initialize this memory before loading the main firmware.
2.2 D213ECV — 128 MiB packaged DDR3
The D213 runs its independent 600 MHz-class RISC-V graphics service, GE/DE drivers, asset cache and display buffers. The manufacturer lists D213ECV with 128 MB built-in DDR3 [S2]. Frame ownership, cache/DMA synchronization, and memory pressure during video decode require software validation.
2.3 ECP5-45F — 32 MiB x16 SDR SDRAM
Candidate: Alliance Memory AS4C16M16SA family (256 Mbit, 16M × 16). This is conventional single-data-rate SDRAM, not DDR3. It provides local texture, color, depth, and geometry storage for a custom rasterizer [S4].

2.4 ECP5-12F — 4 MiB QSPI PSRAM
Candidate: AP Memory APS3204L-3SQN family, 32 Mbit / 4 MiB, 3 V QSPI PSRAM [S5]. Intended uses: bounded geometry or collision work queues, lookup tables, and intermediate calculations. This is not a display framebuffer and does not make the 12F a graphics card.
Previously R10 specified no external working RAM on the 12F. The 4 MiB PSRAM is an explicit later design change and requires synthesis, I/O-bank voltage, package-pin, configuration, and RGMII coexistence checks.

3. Single 64 MiB NOR — physical architecture
The simplest COMPONENT COUNT is one NOR, but the simplest BOOT ARRANGEMENT may not be. One shared chip requires a controlled firmware distribution process; the four devices should not all directly drive its SPI wires.
3.1 Preferred wiring model
Connection
Responsibility / proposed physical contract
NOR → F133-B
One dedicated SPI/QSPI boot bus. F133 is sole NOR bus master.
F133 → ECP5-12F
Lattice Slave SPI or other vendor-supported configuration mode; F133 sends image read from NOR.
F133 → D213ECV
Internal USB host/device link after F133 boot; transport protocol and flashless start are NOT validated.
D213 → ECP5-45F
D213 sends 45F bitstream using vendor-supported configuration pins; source delivered from F133.
45F ↔ D213
D213 PBUS carries control, geometry descriptors, and return tile data only after FPGA configuration.

Established vs unproven
Lattice documents CPU-managed configuration of an ECP5 via Slave SPI with images stored in the CPU SPI flash [S3]. ArtInChip documents USB firmware upgrade for D21x [S2], but that alone does NOT prove a D213ECV can execute full firmware loaded directly into DDR without its own NOR/eMMC. R10 must not depend on this assumption at fabrication.

3.2 Flash device selection
Provisional reference: Winbond W25Q512JV, 512 Mbit (64 MiB), SPI/Dual/Quad NOR [S6]. Select the exact package and voltage after checking the F133 pad, assembler capability, erase geometry and 3-/4-byte address-command behavior.
Place the immutable first-stage boot image at low addresses accessible with conservative power-on ROM commands.
Validate F133 boot ROM behavior with this exact 512-Mbit flash device, including power-up address mode and any Quad-enable state.
High addresses require supported 4-byte or extended addressing; do not assume boot ROM can read the whole 64 MiB.
Use flash write protection and a recovery-programming header; make update failure survivable.

Update protocol rules
Boot and recovery stay readable even if a power cut interrupts a firmware update.
Write inactive slot first; stream-verify hash/CRC; atomically switch the manifest; require a successful-boot acknowledgement.
Keep at least two independently stored manifest records with monotonically increasing generation counters and integrity checks.
A 3 MiB metadata/reserve area cannot stage a full 16 MiB D213 image; updates must stream directly into its inactive slot.
Measure final compressed/uncompressed FPGA bitstream sizes. Fit of the actual 45F golden and application images in 3 MiB each is mandatory.

5. Boot, update and failure recovery
5.1 Proposed normal boot (one NOR)
Apply regulated power; hold the D213 and both FPGAs in reset / unconfigured states as needed.
F133 boot ROM reads the low-address first-stage image from the shared NOR.
F133 validates boot manifests, initializes 64 MiB DDR2, and selects a healthy A/B main firmware slot.
F133 loads and verifies the ECP5-12F configuration over its dedicated FPGA configuration link. The F133 must remain bootable if the 12F is blank.
F133 attempts documented D213 startup/download over the selected internal host connection. This step is a hard feasibility gate until boot ROM and code-execution details are proven.
When D213 is running from its own 128 MiB DDR3, it initializes display hardware and establishes an F133 graphics-service handshake.
D213 receives and configures the 45F bitstream, verifies status and initializes PBUS FIFOs plus local 32 MiB SDRAM.
D213 displays a complete frame; F133 enables the game runtime. If 45F fails, retain safe 2D diagnostics.
5.2 Update and rollback
Updates are versioned bundles with separate F133, D213 and FPGA payloads. An update never directly overwrites the last known-good image. During validation, the F133 records the selected partition, code version, hardware revision, image length, CRC/hash and last successful boot.

6.2 Capacity does not equal speed
A 32 MiB x16 SDR SDRAM may provide a much more useful random/burst texture path than the earlier 8 MiB QSPI PSRAM design. Its bus and FPGA controller carry real logic/pin/PCB costs. The 12F QSPI PSRAM, by contrast, remains suitable for infrequent large batches rather than high-rate texture fetches.
60 fps rendering gate
At 320 × 240 3D and 60 frames/s, the 45F→D213 path must reliably exceed 9.216 MB/s of COLOR payload plus safety margin and protocol overhead. That is a minimum traffic floor, not an acceptance benchmark by itself.

7.2 If one NOR fails the boot test
Fallback: keep one 64 MiB F133-owned NOR, and add the smallest proven D213-local boot NOR necessary. Both FPGA images can still be maintained centrally and configured by their associated processors. That produces TWO flash packages, not four. Reserve unpopulated D213 flash footprint/test pads on the first prototype if board area permits.

7.4 Change record
Supersedes the earlier R10 external-memory assumption of no 12F RAM (now 4 MiB QSPI PSRAM). Supersedes the earlier four-NOR proposal (now one 64 MiB NOR as a CONDITIONAL target). Preserves F133 64 MiB and D213 128 MiB package RAM, plus ECP5-45F 32 MiB SDR SDRAM. Does not supersede the separate architecture feasibility gates.

Questions to close before board routing
Can D213ECV execute bare-metal graphics firmware downloaded over USB after reset, WITHOUT its own boot flash?
Can the exact 64 MiB NOR chip boot F133 through the factory power-on address mode, while the runtime accesses all 64 MiB?
Can the chosen 12F package expose RGMII, QSPI PSRAM and configuration pins simultaneously with acceptable timing?
What pinout, supply rail and SDRAM refresh/timing margin does the 45F require for x16 SDR SDRAM?
Can we demonstrate a failure-resilient update scheme while NOR remains the only persistent system store?
