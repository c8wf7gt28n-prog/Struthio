# AI platform handoff

## Source authority

The project has three independent physical layers (PCB, CASE, ACRYLIC); the firmware is `firmware/slim4` in the repository. Keep each layer in its own folder and preserve the shared coordinate system: **millimetres; SLIM4 PCB XY (R21 = R22 = R23 = R24 = R25 = R26 datum; Y down, as in KiCad); board bottom at Z=0; +Z toward the front.** The R26 PCB file is the locked motherboard for ordering (check A1). Do not change its footprint positions, nets, outline, or routing while editing the case or acrylic. If a proposed change needs a PCB edit, describe the conflict and request an explicit decision instead of moving the board silently.

| Parent | Main editable source | Neutral interchange | Current scope |
|---|---|---|---|
| PCB | `LAYERS/01_PCB/SLIM4_R26.kicad_pcb` (edits from R25: `R26_FROM_R25/`; from R24: `R25_FROM_R24/`; from R23: `R24_FROM_R23/`; from R22: `R23_FROM_R22/`; from R21: `R22_FROM_R21/`) | `SLIM4_R26_PCB_LAYER.json` (written by `CHECKS/export_pcb_layer.py`) | R26: R23's four plug-and-play ports (panel tail into J1 on the front, JST PH battery with reverse protection, PicoBlade speakers), R24's power layout, R25's corrected In2 planes at U1, and R26's DSI as matched 100 Ω coupled pairs over unbroken ground with impedance control ordered (`CHECKS/R26_DSI_REPORT.md`); JLCPCB order files ready; U1 stock to confirm |
| CASE | `LAYERS/02_CASE/build_r12.py` | `STRUTHIO_CASE_R12.step/.stl`; per-sublayer STEP (STL also for front shell, rear shell and controls); `CASE_LAYER_R12_MESH.json` | R12 complete enclosure: front shell, rear shell, controls, screen stack (LCD, tape frame, cover glass), internals (battery, speakers, lap tape, FPC/harness reserves) |
| ACRYLIC | `LAYERS/02_CASE/build_r12.py` (film section and `P`) | STEP, STL, SVG, DXF; generated cut spec `ACRYLIC_LAYER_R2_CUT_SPEC.json` | clear face film R2 and cutline: 0.175 PET + 0.025 OCA, unprinted for the prototype |

Cross-layer authority: `CHECKS/convergence_check.py`. A revision is converged only when it reports **0 FAIL**. GATE rows are physical or supplier items that CAD cannot close; they are listed in `PRODUCTION_GATES.md`.

`SLIM4_R26_PCB_LAYER.json` is regenerated from the board by `CHECKS/export_pcb_layer.py`, which takes the outer outline and part heights from `REFERENCES/PCB_R21/SLIM4_R21_PCB_LAYER.json` and the cut-outs from the board (R21's file mirrors 80 pads on rotated back-side parts; the export does not). Both R26 files are hash-locked by check A1.

## How to make a change

1. Read this file, `DECISIONS_R26.md` to `DECISIONS_R31.md`, `PROJECT_MANIFEST.json`, `PRODUCTION_GATES.md` and `CHECKS/R31_CONVERGENCE_REPORT.md` first.
2. Edit one parent layer at a time. Most CASE/ACRYLIC dimensions are in the `P` dictionary at the top of `build_r12.py`; derived positions (screen opening on the active area, film cutouts on the relief, grille on the speakers) follow automatically. The support/clamp post positions (`CLAMP_POSTS`, `REAR_ONLY_POSTS`), the R10 silhouette control points and the FPC/harness route geometry are constants further down `build_r12.py` and are edited there. Record every changed file and dimension in the next revision's changelog.
3. For CASE or ACRYLIC geometry, install the pinned environment (`python -m pip install -r requirements.txt`: CadQuery 2.8, OCP 7.9, shapely, numpy, matplotlib, Pillow), then run from the package root, in this order:
   `python -B LAYERS/02_CASE/export_layer_formats.py` (STEP/STL, SVG/DXF, cut spec, fit summary, viewer meshes, full assembly STEP)
   `python -B CHECKS/convergence_check.py` (must end with 0 FAIL; R31 has 3 FAIL rows, the case pass the owner set aside, in `PRODUCTION_GATES.md`)
   `python -B CHECKS/render_review.py` (sections and views for the change report)
   `python -B CHECKS/build_pcb_viewer_data.py` (studio PCB data)
   `python -B CHECKS/make_manifest.py` (last: PROJECT_MANIFEST.json and SHA256SUMS.txt).
4. Component heights the checks use live in `CHECKS/COMPONENT_ENVELOPES_R26.json`, with their sources. Update that table (not the PCB) when a supplier figure changes.
5. For PCB edits, use KiCad 7.0.x with the bundled project, local footprint library, and project file. Exported JSON is for inspection/interchange, not a replacement for the native board. A PCB edit is a new PCB revision and needs an explicit decision. Script it like `LAYERS/01_PCB/R26_FROM_R25/` (one edit per pcbnew process, then `fill_drc.py` beside the `.kicad_pro`, whose net-class rules DRC needs; give new copper areas distinct priorities so fills are reproducible), then run `CHECKS/export_pcb_layer.py` and `CHECKS/dsi_pair_check.py`, update the A1 hashes in `convergence_check.py`, and rebuild the builder files (which write `CHECKS/R26_FAB_SUMMARY.json`). After a pin change, run `firmware/slim4/tools/check_pinmap.py`.
6. The face film is specified for the prototype (`DECISIONS_R26.md` #9–#11: stack, 0.20 mm edge inset, vent windows, unprinted). Artwork is a later cosmetic revision; keep the screen active area unprinted and the stack at the CAD thickness.
7. Return the revised source files with a change report (see `AI_CHANGE_REPORT_TEMPLATE.md` and `AI_CHANGE_REPORT_R31.md`), the convergence report, renders, and updated checksums (`python -B CHECKS/make_manifest.py`). Do not overwrite this package; create a new revision.

## Interchange files

STEP is the primary CAD exchange for solids; STL is for mesh viewers/printing; SVG/DXF are two-dimensional acrylic cutting references (SVG is Y-down in the shared datum; DXF is Y-up, i.e. the same front view); KiCad remains native for the PCB; JSON supports inspection by tools that cannot open the native application formats. `ASSEMBLY/STRUTHIO_SLIM4_R31_ASSEMBLY.step` combines the PCB, CASE and ACRYLIC layers (PCB solids are derived envelopes, not the PCB authority). `index.html` opens the integrated browser viewer; its CASE and ACRYLIC geometry is loaded from `case-layer-data.js` and `acrylic-layer-data.js`. To publish the viewer, run `python -B CHECKS/build_viewer_bundle.py <folder outside the package>` and deploy that 7-file folder; the package itself stays the source. To produce the files for the PCB house, the print service, and the sticker printer, run `python -B CHECKS/build_builder_packs.py <folder outside the package>` (needs KiCad 7.0.x as well); it never edits the PCB.

Rebuilds are reproducible with the pinned `requirements.txt`: every STL, SVG, DXF and JSON file written by `export_layer_formats.py`, the viewer meshes `case-layer-data.js` and `acrylic-layer-data.js`, the convergence reports and the renders regenerate byte-for-byte. STEP headers carry a fixed timestamp; the only remaining STEP differences between runs are how OCCT orders its colour-style records (part names, colours and geometry identical), so the STEP hashes in `PROJECT_MANIFEST.json` and `SHA256SUMS.txt` change after every export. `CHECKS/build_pcb_viewer_data.py` writes the studio's PCB data: the board geometry in `model-data.js` (outline, parts, pads, tracks, vias, nets) from `SLIM4_R26_PCB_LAYER.json`, plus copper pours, per-part BOM/sourcing, fab status (`CHECKS/R26_FAB_SUMMARY.json`) and the open FAIL/GATE rows; with kicad-cli present it also replots `R26_REAR_BOARD.svg`. Rerun it after the convergence check or the builder files change. `case-r3-data.js` is not written by any script in this package.
