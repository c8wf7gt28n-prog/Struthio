## Acknowledged risks

* **BOOTSEL_SHARED_WITH_SPI0** (PC4, PC5): R07: straps defined as 11 (SMHC0 first) by 10k pull-ups; codes 01/10/11 all try SMHC0 first, only 00 does not. T35 is held in CRESET_N by a 4.7k pull-down until F133 firmware runs, so it cannot pull a strap low. Residual: eFuse BOOT_MODE state of the purchased F133-B lot (bench check).
* **SD_BOOT_REQUIRED** (PF0, PF1, PF2, PF3, PF4, PF5): eMMC (SMHC2) is impossible because it uses PC2-PC7 = SPI0. SPI-NOR/NAND boot would share SPI0 with T35 through a GPIO chip-select; that is not selected.
* **F133_QUAD_IO_UNCONFIRMED** (PD12, PD13, PD14, PD15): F133 DS lists Quad-Output/Quad-Input, not Quad-IO. BT820 Quad mode needs a quad address phase. Baseline uses BT820 SINGLE mode (the default, host commands work only there); Dual/Quad only after register-level confirmation in the F133 user manual and bench test.
* **PSRAM_POWERUP_PULLS** (J18, K20, K14, J20, J16): 2.2 kOhm pull-downs add ~1.5 mA per line while driven high; check T35 drive strength and SI at the selected SCLK
* **MN820_POWER_PIN_WORDING** (CN1.13, CN1.15, CN1.17, CN1.19): R07: RESOLVED FROM REFERENCE SCHEMATIC: VM820C DS v1.1 Figure 5 buck 'VSYS -> 3V3' net VCC3V3 drives baseboard receptacle CN6 pins 13/15/17/19 (Figure 7). The baseboard supplies the module; 'output' is baseboard-side wording. Written Bridgetek confirmation still requested (Q1).
* **MN820_MODULE_VOH_2V4** (CN1.84, CN1.90, CN1.92, CN1.94): MN820 DS Table 3 guarantees only VOH >= 2.4 V at module level; F133 VIH = 0.7*VCC-IO needs VCC-IO <= 3.428 V. 3V3 rail tightened to 3.20-3.40 V; margin +0.02 V on the module spec (chip-level BT820 VOH = VCCIO-0.4 would give ~+0.6 V). Measure VOH on the bench.
