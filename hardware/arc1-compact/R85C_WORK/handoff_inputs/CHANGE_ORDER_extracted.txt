
ARC-1 COMPACT
R8.5 — ECP5-45FDESIGN CHANGE ORDER
Controlled replacement of the optional FPGA enhancement subsystem
STATUS  /  OWNER-DIRECTED CANDIDATE — ACCEPTANCE CONDITIONAL
Decision in one paragraph
Replace the R08 Efinix Trion T35F400C3 accelerator with a Lattice ECP5-45F candidate to favor an established, reproducible, fully open FPGA RTL-to-bitstream workflow. This change does NOT authorize a schematic-only substitution. R8.5 must prove a legal part/package and pin map, FPGA power/reset/configuration, host communications, 8 MiB QSPI PSRAM access, usable accelerator performance, and independent recovery. Do not begin R09 physical routing until these gates are satisfied.
PROTECTED BASELINE  Allwinner F133-B + 64 MiB DDR2; direct F133→BT820B/MN820 graphics and 128 MiB graphics RAM; 32 MiB NOR primary boot; microSD game library; USB-C device/recovery; stereo I²S. The FPGA is never in the primary display or boot dependency chain.

1  Reason for change and engineering boundaries
1.1  Why this is not a feature increase
ARC-1 is a fixed-hardware console intended for a decade of new game engines and optimized FPGA configurations. The owner prefers an ecosystem in which FPGA builds remain possible from archived source using community-maintained tools. ECP5 is proprietary silicon, but Yosys + nextpnr-ecp5 + Project Trellis provide an established open toolchain. Efinity is vendor-controlled; a complete analogous open flow for Trion T35 is not established. [S1–S4]

1.3  Decisions that cannot move in R8.5
F133-B retains CPU, NOR boot, microSD management, USB device recovery, audio and game runtime.
F133↔BT820/MN820 remains the direct graphics-command path, independent of FPGA status.
No mandatory T35/ECP5 path to the LCD or external HDMI video adapter.
Do not add radios or USB thumb-drive mass-storage features in this change. USB1 host gamepad planning remains a separate controller requirement.
The exact display/monitor interface remains an R09 decision; do not freeze R09 connector or video converter here.
CORRECTION TO EARLIER COMPARISONS  The 44K and 31,680 figures are not interchangeable LUT counts. Actual RTL mapped into both architectures, with timing closure, is the valid performance comparison.

2.1  Mandatory electrical isolation
F133 SPI0, PC4/PC5 boot-select straps, NOR flash and the old FPGA mailbox are a known design conflict. Replacing T35 with ECP5 does not resolve that conflict by itself. R8.5 must explicitly show which SPI controller/peripheral, pins, chip selects and direction are used at power-on, during F133 ROM boot, and after the FPGA is configured. [S7]
2.2  Requirements before schematic approval
Deliver a single machine-readable F133 pin-mux matrix: NOR, BT820 SPI1, ECP5 operational link, ECP5 configuration, microSD, USB0/USB1, I²S, interrupts and diagnostics.
Demonstrate F133 NOR boot and USB/FEL service with ECP5 held unconfigured, not merely with cooperative ECP5 firmware.
Reserve an independent JTAG service connector; define access to PROGRAMN, INITN and DONE.
No T35 footprint, I/O bank assumptions or configuration circuits may be copied without reassessment.

4  FPGA configuration and game-change protocol
4.1  Required operating state machine
State
 | F133 action
 | FPGA guarantee
 | P0 / Reset
 | Boot from permanent 32 MiB system NOR
 | FPGA cannot drive shared boot signals or block BT820.
 | P1 / Launcher
 | Run graphics without FPGA; enumerate games from microSD
 | FPGA may be blank, held reset or in benign diagnostic state.
 | P2 / Select game
 | Read per-game configuration file; verify checksum/hash/version
 | No I/O contention; DDR/PSRAM access quiesced before reconfigure.
 | P3 / Configure
 | Assert PROGRAMN; await INITN; stream appropriate bitstream via selected supported mode
 | DONE timeout and explicit failure result.
 | P4 / Handshake
 | Read accelerator protocol/ABI version and capabilities
 | No game work until FPGA signature and self-test pass.
 | P5 / Play
 | Submit jobs; read back results; queue graphics commands directly to BT820
 | Predictable latency and bounded error handling.
 | P6 / Fault
 | Disable accelerator service, reset or retry; return to safe launcher
 | No impact to NOR boot, USB recovery or base graphics.
 | 
ECP5 configuration is SRAM-based: a configuration survives until reset/reconfiguration or power loss. Lattice documents JTAG, slave SPI and additional modes, plus PROGRAMN/INITN/DONE status and refresh behavior. A Linux kernel FPGA manager supports ECP5 slave-SPI full reconfiguration, but its existence does not mean this exact F133-B firmware already supports it. [S2, S8]
4.2  Distinguish two different SPI interfaces
CONFIGURATION interface: sends complete ECP5 .bit data to sysCONFIG before the user circuit operates; implement as proven slave-SPI or another expressly selected mode.
OPERATIONAL interface: sends command and result frames between F133 and the accelerator circuit after DONE is valid; distinct protocol from configuration.
Neither may interfere with the F133 ROM-accessed 32 MiB NOR flash; dedicated CS alone is not automatically sufficient when BOOT-SEL shares the bus.
External JTAG must be independently serviceable when F133 firmware fails; do not depend solely on normal boot to configure/recover FPGA.
If a dedicated FPGA configuration flash is proposed, justify cost, ownership, update policy and why F133 streaming is insufficient. Do not assume the F133 NOR is transparently shareable.
4.3  Persistent firmware and removable configurations
Base ARC-1 firmware remains in NOR. Game-specific ECP5 bitstreams may reside with game assets on microSD and be loaded only after F133 boot. With no microSD, ARC-1 must still display its launcher and complete BT820, audio and USB diagnostics. Bad or absent bitstreams must never prevent basic operation.

5  Host protocol, memory and performance
5.1  Replace the old T35 mailbox correctly
The operational message protocol is intended to remain stable at the software level even though the hardware interface changes. Claude must separately select pins, voltage levels, maximum clock frequency, direction, interrupt/status line and bus ownership. Avoid describing any host-through-FPGA graphics command path: F133 commands BT820 directly.

5.2  External PSRAM engineering tests
Bring up APS6404L 8 MiB QSPI controller from power-on, including CE#, CLK, IO[3:0], reset and default bus levels.
Implement JEDEC/PSRAM command and mode handling from the exact device datasheet; test fixed patterns, walking bits, random addresses, and page/burst crossings.
Report sustained and worst-case transfer rates, read latency, bank-voltage tolerance and worst-case timing margins.
Do not conflate 8 MiB FPGA PSRAM with F133 64 MiB DDR2 or BT820 128 MiB DDR3L: none is a unified address space.
5.3  Reality-based acceleration benchmark
Provide benchmark jobs representative of ARC-1: 2D vector/matrix transformation, collision batches, particle updates and one deliberately DSP-heavy stress test. Measure or simulate CPU-only compute time, FPGA computation time, host transfer time, dispatch overhead and total frame contribution. Prefer meaningful 60 Hz frame-time wins to impressive logic utilization.
HARD STOP  A design that fits 45F but cannot meet intended clock/timing or spends more time moving data across SPI than calculating it is not a successful migration. DSP count decreases from 120 to 72: document multiplier mapping and sharing explicitly.

6  Open-source build and evidence standard
6.1  Required reproducible build
The new accelerator shall build on Linux using license-free tools: Yosys for Verilog synthesis, nextpnr-ecp5 for timing-driven place/route, Project Trellis for device/bitstream generation, and an independent service/programming path such as JTAG/openFPGALoader. Pin the exact source commits and package constraints. [S3, S4]
Open-tool limitations must be disclosed: Project Trellis documents LUT logic, BRAM, PLLs and other FPGA elements; certain multiplier behaviors require manual MULT18X18D primitive instantiation, and advanced DSP inference/cascades may not be supported in the selected open tool versions. [S3]
6.2  Build artifacts Claude must produce
An offline-rebuildable repository/archive with HDL source, testbenches and checksums; no private black-box FPGA IP essential to boot.
Locked Yosys, nextpnr, Project Trellis, simulation, and programmer versions/commits; license notices and build README.
Exact -45k, -6 speed-grade, caBGA381 package target and validated LPF pin constraints exported from source pin-matrix.
Synthesis log with resource counts (LUTs, EBR, DSP, registers, PLLs, I/O) and no accidental latch or unresolved module.
Place/route report with constraints for every primary and generated clock and maximum host/PSRAM paths.
Raw binary or .bit FPGA image with size, hash, firmware ABI, reproducibility comparison and programming test procedure.
Cross-simulation with F133 host driver and error injection: absent FPGA, invalid bitstream, DONE timeout, corrupted SPI frame, stuck BUSY, PSRAM failure.
Independent external-JTAG recovery instructions, pinout and fixture hookup for first physical PCB.

7.1  Failure-injection table required
At minimum: blank NOR, wrong NOR BOOT straps, FPGA at power-off, ECP5 configuration CRC fault, PROGRAMN held active, QSPI CE# stuck active, PSRAM missing, FPGA-CPU protocol version mismatch, F133 software crash mid-configuration, bad microSD, and ECP5 rail sequencing fault. 8  Work sequencing and Claude handoff directive
8.1  Controlled execution sequence
1.  Freeze R08 master snapshot and identify every T35 net, RTL primitive, firmware driver and test that R8.5 will change.
2.  Confirm LFE5U-45F exact suffix and caBGA381 package availability; open Lattice latest data sheet, sysCONFIG and hardware checklist.
3.  Create a T35→ECP5 functional delta table (power, package pins, clocks, reset, FPGA configuration, host link, 8 MiB PSRAM).
4.  Update source schematics and pin matrix; redesign F133 SPI0 NOR/FPGA ownership without touching direct BT820 SPI1 path.
5.  Port HDL to vendor-neutral interfaces and build via Yosys/nextpnr/Trellis; investigate unsupported DSP primitives explicitly.
6.  Port F133 configuration loader and versioned mailbox; demonstrate no-FPGA launcher and recovery behavior in tests.
7.  Produce QA bundle, corrected component BOM, power budget, native ERC and evidence-based risk register.
8.  Ask for an independent R8.5 review before R09 placement/routing.
8.2  Stop-work / revert conditions
No legal caBGA381 pinout and power bank allocation can be assigned around the NOR-first boot and BT820 command routes.
The full open-toolchain cannot create an acceptable routed image for our actual workload and selected device/package.
The 8 MiB PSRAM or game-to-game FPGA loading lacks a recoverable hardware implementation.
The new FPGA creates mandatory boot or display dependencies not present in the R08 baseline.
Sourcing, assembly rules, or power consumption make the selected part materially unsuitable.
If any stop condition occurs, submit a documented option (fix pin mapping, change package, evaluate a different 45F grade, or revert to T35) instead of silently upgrading to 85F or claiming migration success.
