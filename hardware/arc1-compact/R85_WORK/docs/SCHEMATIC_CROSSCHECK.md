## What the ERC means and does not mean

- **0 violations** means: every power input is driven (regulator/switch outputs or explicit PWR_FLAGs on externally fed or 0 Ω-linked rails); no global label is used only once; no pin is left dangling; and there are no pin-type conflicts.
- ERC does **not** check part values, timing, voltage compatibility or footprints. The first ERC pass found 9 real
  issues, and each was fixed in the source rather than waived:
  - flags were missing on rails fed through the 0 Ω staging links and the PTC;
  - F133 pin 47 is typed NC but carries the DNP DZQ option;
  - the T35 DDR_VREF tie to GND was typed bidirectional.

## 1:1 cross-check (`cad/check/crosscheck_r08.py`, run by the R08 runner)

| Check | Compares | Result |
|---|---|---|
| A | KiCad netlist ↔ board plan: component set, footprint and value per component, node set of every named net, every unconnected pin declared as an intended no-connect | 0 mismatches |
| B | every symbol pin number ↔ the pad names in the footprint file actually assigned (KiCad 9 library or ARC1_R08.pretty), both directions | 0 mismatches over 36 footprints |
| C | Efinity pin table ↔ schematic U18 ball/net ↔ T35 pinout resource/bank ↔ RTL top-level ports and directions (every RTL port has an Efinity source and vice versa) | 0 mismatches (17 GPIO, 33 RTL ports) |
| D | `firmware/include/board_pins_r08.h` ↔ schematic F133 GPIO→net | 0 mismatches (53 pins) |

The cross-check proved its value: it caught a SLIM4 footprint written in the legacy unquoted pad syntax.

**Limits:**
- These representations are generated from one source, so agreement shows that nothing was lost or altered in
  translation. It does not show that the source is right.
- Correctness of the source rests on the manufacturer facts in `sources/`, on the self-authored rules in
  `board/check_board_r08.py` (11 rules, 15 hazard mutations caught), and on the calculations in `analysis/`.
