1 Why R08 must be interrupted

Adding permanent NOR changes startup pin states, board-level boot
selection, SPI0 ownership, manufacturing programming and fault recovery.
These are schematic-level choices; attempting them after R09 routing
would create avoidable rework. Conversely, selecting an LCD now is
unnecessary. R08 shall finish the common LVDS/graphics architecture but
explicitly carry panel-dependent circuitry as an R09 dependency.

3 Non-negotiable power-on behavior

1.  Normal, SD absent: Cold power-on reads NOR, initializes system RAM,
    talks directly to MN820, and reaches an empty-library launcher. No
    FPGA configuration is necessary.

2.  Normal, SD present: The same NOR system starts first; subsequent
    card detection/mount reads available game packages. A game card
    shall not replace system firmware.

3.  NOR blank or corrupt: A user-accessible independent ROM/FEL
    programming route allows diagnosis and reprogramming without
    executing NOR-resident code.

4.  T35 failed or unconfigured: Boot, graphics and USB recovery remain
    possible, provided the defective FPGA is non-driving on any shared
    bus.

5.  SD removed during gameplay: Stop new card I/O and return to the
    launcher safely where possible; reject incomplete saves rather than
    corrupting data silently.

4 F133 boot ROM, SPI0 and boot straps — blocking design issue

The F133 manual describes both GPIO and eFuse boot-source selection.
Under GPIO selection, BOOT-SEL[1:0]=00 prioritizes SPI NOR. The previous
11 strap concept targeted SD/eMMC and must not remain unquestioned.
PC4/PC5 are shared between boot selection and SPI0 data; the strap
network must reliably establish boot priority at reset while permitting
subsequent SPI signaling. [S1,S2]

5 Mandatory 32 MiB NOR: capacity, addressing, component qualification

Owner storage target = 32 MiB = 256 Mbit = 33,554,432 bytes. W25Q256JV
is a reference family, not a frozen BOM line. A particular Winbond
variant can be marked “not recommended for new designs”; select by an
exact orderable suffix, not the generic W25Q256JV label. Winbond parts
at this density may power up in 3-byte address mode and need
extended-address handling above the first 16 MiB. [S3,S4]

-   Boot0 / boot-ROM prefix — Show exact offset, ROM-recognized
    image/header, read opcode, address width, size bound, power-up
    address mode and valid first-stage load path. Keep ROM-required
    startup data in the reachable low-address region.

-   Full device addressing — Prove how the loaded driver addresses the
    second 16 MiB (0x01000000 and above). Include JEDEC/SFDP detection,
    4-byte instructions or bank-register strategy and reset-mode safety.

-   Image-size ledger — Measure the actual boot, system, graphics/audio
    drivers, launcher, FPGA diagnostic resources, recovery and update
    images. Do not silently assume Linux fits in 32 MiB or 64 MiB system
    RAM.

-   Programming and lifecycle — Provide first-assembly programming (FEL
    or external programming fixture), update/rollback or recoverable
    update strategy, verify/readback, write-protect and status-bit
    configuration.

-   Parts and footprint — Choose exact P/N, package, vendor status,
    voltage, JEDEC ID, QE/reset options, sourcing and JLCPCB assembly
    feasibility. SOIC16 vs WSON8 vs BGA has different diagnostic
    tradeoffs.

6 USB-C: power sink and diagnostic device, not thumb-drive host

Remove USB mass-storage HOST requirements, USB VBUS sourcing to
accessories and host-only protection/power-switch paths. Do not remove
the CPU’s USB0 device data connection or the ability to enter ROM/FEL.
The F133 documentation distinguishes USB0 dual-role from USB1 host.

Require a specific recovery procedure: power from a safe source, hold a
documented force-FEL action, assert/release reset, observe USB ROM
enumeration, upload a small SRAM stub and program/verify NOR. Board
provisions must support this even with NOR erased. USB Type-C CC
implementation, allowable sink current, backfeed prevention and
battery/USB power-path arbitration require review. Generic sunxi FEL
guidance is not a substitute for proving the exact F133 boot entry and
package signal. [S1,S5]

7 microSD: removable games, not system boot

Use the F133-supported SD host interface with verified mux and signal
voltage. Card detect, ESD, power switching where needed,
insertion/removal signaling, filesystem and write-safe saves must be
documented. An empty card slot is a normal startup condition. A
malicious/corrupted game package should not prevent the NOR launcher
from booting.

-   Media interface proof — Map SMHC pins, DAT0–DAT3, CLK, CMD, detect,
    VDD, pull resistors, I/O levels and power sequence. Avoid reusing
    conflicting SPI0/boot pins.

-   Runtime behavior — Scan a versioned game manifest; reject invalid
    packages; distinguish card absence, corruption and unsupported
    format; journal or atomic-rename saves where suitable.

-   Test matrix — Boot with no card, empty card, valid games, faulty
    filesystem, insertion during launcher, removal during save, sudden
    power loss.

Evidence categories must be kept distinct: (A) manufacturer-published
facts, (B) electrical calculations, (C) native CAD/EDA tool reports, (D)
software simulation and (E) actual physical hardware observations. R08
can provide A–D. No one has yet performed E on an ARC-1 production PCB.

11 R08 completion is NOT manufacturing approval

R08 completion means the core electrical architecture is internally
consistent, represented in native engineering sources, and thoroughly
checked to the extent possible without hardware. It does not mean a
board has been routed, fabricated, powered or successfully booted. R09
will select LCD and mechanical constraints and route the PCB; R10 should
independently audit the final design before a first JLCPCB order.
